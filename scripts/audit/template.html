Kidrove Branch Audit
Code audit · 14 Oct 2026

aditya → backend_auth

Everything that changed between the aditya branch and the current local code: what was fixed, how to check it by hand, and every file touched. aditya is fully contained in backend_auth, so this is a straight list of additions with no conflicts.

What was fixed

Grouped by area, most severe first. The code on the right is the commit to look at.

Security 9

  • Critical

    Cross-account access (IDOR)

    Vendors could list another vendor's ticket holders (customer names and contacts), claim any event, and read another event's cancellation contact list. Any logged-in user could open a child's student record. A paid Stripe payment from one order could be replayed to mark a different, pricier order as paid. Galleries, reviews, certificates and uploads had similar gaps.

    ace00e7
  • Critical

    Public default password TempPass123!

    Accounts created by an admin with a blank password got TempPass123!, which the admin screen displayed. Anyone could log into them. A password of 8+ characters is now required, and that literal is rejected.

    c1f769e
  • High

    Health check leaked internal data

    /health and /api/health showed user and order counts and Redis details to the public. /health/redis needed no login. Both now show only up/down to the public; Redis details are admin-only.

    af16cb3
  • High

    Email library vulnerabilities

    nodemailer 7 had SMTP and header injection, SSRF and credential-leak flaws on every email sent. Upgraded to version 10.

    7d62620
  • High

    Security headers missing on web pages

    nginx dropped X-Frame-Options, nosniff and HSTS on every HTML page and static file, so clickjacking and HTTPS-downgrade protection were off.

    6df68a6
  • Medium

    Content-Security-Policy (report-only)

    Added a CSP to the frontend in report-only mode, with violation reports logged by nginx. It blocks nothing yet; enforce it after about a week of clean reports.

    a54efb2
  • Medium

    Oversized request bodies

    The API accepted 10 MB JSON bodies on every route. Now 1 MB, with bulk imports kept at 10 MB.

    a531948
  • Medium

    Employees with no real vendor

    An admin-created employee without a vendor was linked to itself and couldn't scan any ticket. Now refused with a clear error.

    c1f769e
  • Low

    Phantom 'superadmin' role

    Role checks referenced a role that doesn't exist. Removed; no change in access.

    873d1cb

Payments 4

  • Critical

    Paid orders cancelled by the seat-expiry sweep

    The 15-minute sweep cancelled every pending order without asking Stripe. If the confirmation was missed, a customer who paid lost their booking. It now checks Stripe first and confirms paid orders instead.

    6f29526
  • High

    Failed Stripe webhooks were never retried

    The webhook told Stripe "received" before processing and marked the event done up front, so a database blip lost the event. It now processes first and answers 500 on failure, so Stripe retries.

    1650ae4
  • High

    Pasted Stripe secret keys charged customers with no booking

    With a pasted key the payment is created on the vendor's own Stripe account, but confirmation looks it up on the platform account. Saving a pasted key is now blocked (409); Stripe Connect is unaffected.

    f3745b5
  • Medium

    Webhooks could be rate-limited

    Stripe webhooks counted toward the API rate limit, and Stripe retries on 429. Webhooks and health checks are now exempt, and the general limit rose from 100 to 600 per minute per IP.

    3789168

Reliability & operations 7

  • Critical

    Background jobs never ran

    Every BullMQ job (emails, QR codes, tickets) failed with "pipeline[functionName] is not a function". Fixed by disabling ioredis auto-pipelining.

    4b792f2
  • High

    Seed scripts could wipe production

    Seven destructive seed scripts would run against any database. They now refuse production and non-local databases unless ALLOW_DESTRUCTIVE_SEED=yes.

    4b792f2
  • High

    Deploys left the worker on old code, with no database backup

    deploy.sh reloaded only the API and backed up only built files. It now reloads the worker too and takes a mongodump first.

    e2a58ac
  • Medium

    No automatic post-deploy check

    Added scripts/smoke.sh. deploy.sh runs it and fails the deploy if health, auth protection, the events API or the frontend are broken.

    49dcb2b
  • Medium

    No pre-deploy safety check

    Added npm run check:predeploy (read-only). It flags seed passwords, broken vendor links, lost payments, staff still on TempPass123! and pasted Stripe keys.

    a27a5d6 · f3745b5
  • Medium

    Logs grew without limit

    Logs now rotate daily and are gzipped (15 days, 30 for errors), with a separate file per PM2 app.

    4b792f2
  • Low

    Unreadable SMTP errors and a shared Redis

    SMTP failures were logged one character at a time. QUEUE_PREFIX now lets queues share a Redis server safely.

    af0c2af · 8db3444

Bugs & user experience 6

  • High

    Wrong password wiped the login form

    A failed login blanked the whole app while loading, so the form reset and the error message never showed.

    aeffc8e
  • Medium

    Registration data was unwrapped twice. The blog editor crashed and lost the form when switching from HTML to Visual.

    aeffc8e
  • Medium

    Every visitor saw the server's currency

    Currency was detected from the server's IP, not the visitor's, and burned the shared lookup quota. Now uses the visitor's IP, cached per IP.

    b415d6f

    Online events without a location returned a 500

    Vendors couldn't create online events that have no physical location.

    1095f1f

    a2c343b
  • Low

    SEO and accessibility

    Event cards are real links (open in a new tab works). The home page has a single h1.

    3ceda63 · f0cc944

Performance 2

  • Medium

    First page load

    JavaScript on first load fell from about 768 KB to 302 KB gzipped: Firebase loads on demand, the vendor-libs grab-bag chunk is gone, and the admin chat widget loads only on admin pages.

    bb9c302 · 9774499

    Eight large PNG/JPG images were converted to WebP (7.9 MB to 504 KB). The service worker no longer precaches every PNG (16.2 MB to 7.6 MB per new visitor).

How to test manually

Use the local Docker stack for most checks. The production checks need the deploy done first.

Local setup

docker compose up -d
docker compose exec -T backend npx ts-node src/scripts/seed.ts
# Frontend http://localhost:3000 · API http://localhost:5001 · Mailpit http://localhost:8025
# Accounts: admin@gema.com / admin123 · vendor@gema.com / vendor123 · customer@gema.com / customer123

Cross-account access

Local
  1. Log in as vendor@gema.com / vendor123 and note one of your event IDs.
  2. Register a second vendor at /vendor/register and log in as them.
  3. In the browser, open /api/tickets/event/<first vendor's event id> and /api/events/<id>/affected-orders on the API.
  4. Log in as customer@gema.com and open /api/students/<a child id that isn't yours>.

ExpectedThe second vendor and the stranger get 404 or 403. The owner and an admin still see the data.

Default password removed

Local
  1. As admin@gema.com / admin123, open Admin → Users → Create user.
  2. Leave the password blank, then try TempPass123!.
  3. Create an employee with no vendor selected.

ExpectedAll three are refused with a clear message. A user with a real 8+ character password is created.

Health check privacy

Local + production
  1. curl https://api.kidrove.com/api/health
  2. curl -o /dev/null -w '%{http_code}' https://api.kidrove.com/health/redis

ExpectedThe first shows status only, with no metrics or counts. The second returns 401.

Real paid booking and refund

Production
  1. Book a cheap event with your own card.
  2. In Stripe → Developers → Webhooks, check that payment_intent.succeeded was delivered with 200.
  3. Check My Bookings shows the ticket with a QR code, and that the confirmation email arrived.
  4. Refund the payment in Stripe.

ExpectedThe order goes to confirmed/paid, then to refunded after the refund.

Webhook retry

Local (Docker, with STRIPE_API_KEY set)
  1. Make a test-card booking, but run docker compose stop mongo just before paying.
  2. Check the stripe container log: the webhook delivery got 500.
  3. docker compose start mongo, then resend the event: stripe events resend <evt_id from the log>.

ExpectedThe resend gets 200 and the order becomes confirmed with its tickets. In production, Stripe resends automatically.

Pasted Stripe key blocked

Local
  1. As vendor@gema.com, open Payment settings and paste a Stripe secret key.

ExpectedSaving is refused with a message to use Stripe Connect. Connect onboarding still works.

Paid orders survive the seat sweep

Local
  1. docker compose stop stripe, so no webhook reaches the backend.
  2. Book with a test card and close the tab before the confirmation page loads.
  3. Wait 20 minutes (seats are held 15 minutes; the sweep runs every 5).

ExpectedThe order is confirmed, not cancelled. The worker log says it was reconciled.

Background jobs and email

Local
  1. Register a new account, then open Mailpit at http://localhost:8025.
  2. Book a free event as a customer.

ExpectedThe verification email arrives, and the ticket email arrives with a QR code.

Login and forms

Local
  1. On /login, enter a wrong password.
  2. In Admin → Blogs → Create, switch the editor from HTML to Visual and back.
  3. As a vendor, create an online event with no location.

ExpectedThe error shows and the form keeps its values. The editor doesn't crash. The event saves.

Request size limit

Local
  1. Send a 2 MB JSON body to POST /api/auth/login.
  2. Upload a booking CSV via the vendor booking import.

ExpectedThe login request gets 413. The import still works.

Security headers and CSP

Production, after the nginx change
  1. curl -sI https://kidrove.com | grep -iE 'x-frame|strict-transport|content-security'
  2. Browse a few pages, then on the server: tail /var/log/nginx/csp-reports.log

ExpectedAll three headers are present. Reports appear in the log; nothing on the site is blocked.

Speed

Production
  1. Open kidrove.com in a private window with DevTools → Network.

ExpectedNo vendor-libs file loads. About 300 KB of JS gzipped on first load. Banners load as .webp.

Deploy checks

Server
  1. npm run check:predeploy in backend/ against the production database.
  2. ./deploy.sh, then ./scripts/smoke.sh.

ExpectedThe pre-deploy check lists anything needing attention. The deploy ends with all smoke checks passed.
